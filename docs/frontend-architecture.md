# Frontend composition and dependency ownership

The dependency graph is generated by dependency-cruiser, including imports, re-exports, dynamic
imports and type imports. Run `pnpm architecture:graph` for JSON; production feature relationships
and cycles appear in its `folders` section. The checked-in
[graph snapshot](frontend-feature-graph.json) records acceptance. Shared capabilities cannot
import application/features through aliases or relative barrels, and features cannot import page
composition. This prevents moving a cycle into a shared directory without changing ownership.

## Session, composer and review composition

The original graph contained six cyclic edges between composer, sessions and review. All six
are removed. Composer and review may consume session model capabilities; sessions have no
reverse dependency on their UI. Composer does not consume review and review does not select a
composer store. The conversation/subagent rendering separation removes the remaining two
cyclic edges. The feature graph is acyclic and the checker rejects any nonempty cycle baseline.

| Owner                                                      | Responsibility                                                                                                                                                                                                   |
| ---------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `app/session/SessionHeader.tsx`, title/dialog helpers      | Page header composition: session identity and lifecycle actions, workspace presentation and editor integration.                                                                                                  |
| `app/session/QuickLaunchSessionDialog.tsx`                 | Composes provider/settings selection, native import and composer home drafts; prepares navigation without creating a session prematurely.                                                                        |
| `app/shell/ProjectItem.tsx`, `routes/SessionWorkspace.tsx` | Compose the launch dialog/header/workbench and supply draft actions to the review pane.                                                                                                                          |
| `features/sessions/model/SessionConfigContext.tsx`         | Existing configuration/workspace subscription owner; typed `useSessionWorkspace` and `useSessionConfiguration` views expose focused capabilities without creating another state owner or changing subscriptions. |
| Existing sessions queue/execution/prompt hooks             | Retained focused streaming capabilities. No provider merge, broad transcript subscription or queue lifetime change.                                                                                              |
| `shared/workspace/useGitStatus.ts`                         | React Query workspace status/PR capability using the existing cache keys and invalidation. No dependency on review presentation.                                                                                 |
| `shared/editors/EditorIcons.tsx`                           | Reusable editor brand presentation, independent of session/review features.                                                                                                                                      |
| `features/review/model/composer-actions.ts`                | Explicit page-supplied context attachment/text insertion port. No composer store import, event bus or second draft owner.                                                                                        |
| ReviewView → ReviewFileList → DiffBlock/hunk header        | Pass the same action port to file attachment and hunk quotation. Diff virtualization, query captures and editor/stage/revert behavior remain owned by review.                                                    |
| `features/workbench/ui/Workbench.tsx`                      | Receives the action port and supplies it to the lazily loaded review pane. Deferred terminal/settings/auth/setup loading remains intact.                                                                         |
| Composer draft store, command bar and input hooks          | Retain draft persistence, queued-send integration and pending input/context consumption. Review invokes their page-supplied callbacks.                                                                           |

The existing session configuration subscription still owns its original state. Typed capability
views intentionally do not claim new render isolation; streaming/queue/prompt boundaries remain
separate and retain their regression coverage. Workspace status/editor presentation imports use the shared owner directly; the moved page components are no longer re-exported
from sessions, so feature barrels cannot reintroduce page composition.

Verification includes configuration, draft persistence, context insertion/quotation through an
alternate injected target, captured review/diff virtualization, queue acceptance and navigation.
`performance-browser.mjs --journeys --verify-deferred --architecture-journeys` exercises the
production bundle with synthetic APIs: click/hover/focus/revisit navigation and deferred settings,
draft restoration, review file attachment, hunk quotation and launch dialog cancellation. It
contacts no model provider and rejects unexpected fixture mutations. Timing samples are fixture
measurements, not live-provider performance claims.

## Conversation and child transcript ownership

Conversation composes child views through a deliberate one-way dependency on subagents. Both
features consume shared transcript presentation; subagents no longer import conversation. Shared
renderers accept events, status, preferences and navigation callbacks and never select a parent
session, draft store, settings query or approval API.

| Owner                                                                  | Responsibility                                                                                                                                                                                                                                             |
| ---------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `shared/transcript/ui/ActivityBlock.tsx`                               | Activity summaries, thought display and local disclosure state; callers supply completion/streaming status and thinking preferences.                                                                                                                       |
| `shared/transcript/ui/ToolActivityRow.tsx`, `lib/tool-presentation.ts` | Tool/approval request presentation and output disclosure/copy; no approval execution or parent cancellation.                                                                                                                                               |
| `shared/transcript/ui/ToolOutputContent.tsx`                           | Reusable output, diff and location presentation.                                                                                                                                                                                                           |
| `shared/transcript/ui/AgentTerminals.tsx`, `lib/agentTerminals.ts`     | Event-derived terminal history, replacement/exit handling and existing 64 KiB UTF-8 output bound; no interactive terminal creation.                                                                                                                        |
| `shared/transcript/ui/TranscriptMessage.tsx`                           | Directed session messages; optional participant labels and navigation callbacks supplied by the caller.                                                                                                                                                    |
| `features/conversation/ui/cards/UnifiedActivityBlock.tsx`              | Parent session/turn completion policy and settings subscription; delegates display to ActivityBlock.                                                                                                                                                       |
| `features/conversation/ui/cards/SessionMessage.tsx`                    | Parent stream participant lookup and session-scoped selection callback.                                                                                                                                                                                    |
| `features/conversation/ui/ChildConversation.tsx`                       | Supplies thinking preferences to child rendering at the conversation composition boundary.                                                                                                                                                                 |
| `features/conversation/ui/MainFeed.tsx`                                | Retains mounted parent feed/composer, inert state, focus restoration, session-scoped child selection, history/cancellation transitions and parent approval control.                                                                                        |
| Subagent group utilities/store and `SubagentChatView.tsx`              | Child identity, event grouping, status/connectivity, sibling selection, read-only transcript and observer cleanup. Activity completion derives from the child, independently of parent turn context. Approval notices invoke the parent's review callback. |

Conversation and review no longer forward shared display components. Consumers import the shared
owner directly; shared modules never import feature barrels. The complete frontend and public API
audits are recorded in frontend-state-architecture.md and contracts-architecture.md.

Verification covers child streaming/tool grouping, approval routing, cancellation/disconnect,
session-scoped selection, focus and follower cleanup. A standalone child render test uses no
parent session or settings provider and verifies sibling navigation and terminal output. The
production architecture browser journey also opens child/sibling transcripts, retains the exact
parent feed/composer nodes and draft, returns with Escape, hides selection in other sessions
and restores it on return to the original session. Browser fixtures reject unexpected API mutations; no paid provider is involved.
